# M4.3.2 Task CRUD API Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Complete `M4.3.2` by adding a minimal scheduler-backed `/tasks` CRUD API that stays fully in-memory and reuses the existing `ScheduledTask` contract.

**Architecture:** Keep task runtime state inside a singleton `TaskScheduler`, but hide scheduler ownership behind a thin `TaskService`. Routes perform auth/permission checks and HTTP error mapping only. No DB persistence, execution logs, or runtime trigger integration in this milestone.

**Tech Stack:** Python 3.11, FastAPI, Pydantic, SQLAlchemy ORM models, pytest
