# M6.1.3 CI/CD Design

## Goal

Complete `M6.1.3` by adding the minimal GitHub Actions workflow needed to automatically run the current backend and frontend verification commands on pushes and pull requests.

## Scope

- Add `.github/workflows/test.yml`
- Add any missing dev dependency required by the planned workflow commands
- Reuse the current verified commands:
  - `pytest tests/ -v --cov`
  - `ruff check .`
  - `cd web && npm run lint`
  - `cd web && npm run build`
- Keep the workflow limited to CI verification only

## Out of Scope

- Do not add deployment, release, or publishing jobs
- Do not add secrets handling, environment promotion, or production rollout logic
- Do not expand into container smoke tests or provider-backed acceptance flows
- Do not start `M6.2` documentation work

## Design Constraints

- The workflow must be valid against the current repository layout
- CI commands must be locally reproducible before claiming success
- Keep the workflow minimal and easy to audit
- Preserve current scope boundaries: backend verification and frontend verification only

## Options Considered

### Option A: Backend-only workflow

- Run Python tests and lint only

Pros:
- Smallest configuration

Cons:
- Leaves frontend regressions unchecked
- Falls short of the current verified command set

### Option B: Single workflow with backend and frontend jobs

- One workflow file
- Separate backend and frontend jobs

Pros:
- Minimal while still covering both stacks
- Jobs stay easy to read and parallelize naturally
- Matches the repository’s existing verification habits

Cons:
- Slightly larger than backend-only

### Option C: Full multi-stage pipeline

- Add CI, release, deploy, artifact upload, and matrix jobs

Pros:
- More complete delivery story

Cons:
- Far beyond `M6.1.3`
- Adds maintenance surface without current need

## Recommended Design

Choose **Option B**.

## Workflow Design

### Trigger

- `push`
- `pull_request`

### Backend job

- Ubuntu runner
- Python 3.11
- Install with `pip install -e ".[dev]"`
- Run:
  - `pytest tests/ -v --cov`
  - `ruff check .`

### Frontend job

- Ubuntu runner
- Node setup
- `npm ci` in `web/`
- Run:
  - `npm run lint`
  - `npm run build`

## Dependency Note

The TODO snippet uses `pytest --cov`, but the current `dev` dependencies do not include `pytest-cov`. Add it explicitly so the workflow command is valid both locally and in CI.

## Expected Deliverables

- `.github/workflows/test.yml` exists and reflects the minimal CI design
- `pyproject.toml` includes any missing test dependency required by the workflow
- local execution of the workflow-equivalent commands succeeds
- `docs/progress.md` and `tasks/todo.md` advance to `M6.2.1`
